# 本地实现与人物效果验收

记录日期：2026-11-25。硬件为 RTX 4060 Laptop 8GB、约32GB内存。

## 结论

本地 INT8 推理、九步参考编辑、八步文生图与 RP 接口已实际运行；**“改变场景、衣服和机位，同时自然保持角色本人长相”未通过效果验收。** 通用一致性 LoRA 已加载，不等于拥有角色专属的身份约束。

用户提供的 GPT 图片在整体人物观感、自拍姿态和场景融合上明显优于本次本地结果。本次只有用户提供的320×213图片，没有其完整请求与原尺寸成图，因此是视觉效果对照，不是同参数模型基准。没有重新调用付费 API。

视觉检查：

- A 更靠近第三张的正面取景，并把其脸旁的麦克风带入新图；脸部与身体的结合呈现不自然的观感。参考用途文字没有可靠隔离旧物件。
- B 更贴近主图的脸和姿态，但大量沿用原图的橙色背景、耳饰、黑色颈饰和旧衣服，睡衣没有完整替换。这不能算完成新场景。
- C 改变了背景，比 B 更少沿用原图环境；耳饰、黑色颈饰、旧衣服局部和原取景仍残留。关闭 LoRA 没有同时解决全部问题。
- 先前两身份图的768×1024镜面自拍实现了浴室、手机与睡衣，但脸部明显漂移。四图场景结果仍未获得用户认可的身份保持。
- GPT 图片改变了宿舍环境、粉色睡衣与自拍姿态，人物整体更协调，也没有这些明显的参考物件残留。服装参考本身有粉/白两款；仅出现白色款不能单独算错误。

## 实现验证与边界

原生日志 `logs/native.log` 确认应用384/384个一致性 LoRA 张量。A/B 的 `request.json` 使用0.7；C 的 LoRA 列表为空。请求中的中文完整保存，没有乱码丢失。

无参考文生图、两图编辑与四图编辑均有实际成图；取消请求及其后的下一任务见 `outputs/native-cancel-report.json`。此前已进行 RP 浏览器的本地生图、媒体保存和刷新恢复验证；接口回归使用虚拟引擎，不能验收画质。

本次收尾重新运行：服务端 `python -m pytest -q tests` 为21项通过；RP 的 local/image-generation/image-references/image-scene-consistency/rp-image-generation 五组回归共38项通过。服务端有一条现有的 Starlette/httpx 弃用提示，无测试失败。服务按显式本地预设使用，不自动切换云服务；RP 本地预设说明标为“试验”。

## 后续选择

对需要稳定人物长相的 RP 图片，当前更适合继续使用用户已认可的 GPT 图像服务；本次未修改已保存的服务选择或调用云 API。本地工程保留作场景、物品与简单编辑试验。

若继续研究人物效果，应先做同权重、同输入、同采样的官方/ComfyUI引擎对照，以区分实现差异与模型能力限制；不能直接归咎 INT8，也不能承诺靠增加提示词或切换通用 LoRA 就达到 GPT 效果。人物裁剪输入、角色专属 LoRA等也是独立的新试验，目前没有验证。
